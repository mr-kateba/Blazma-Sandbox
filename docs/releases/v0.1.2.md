## Blazma Sandbox 0.1.2 — إصلاح «الملف مستخدم من برنامج آخر»

كان التحليل يتوقف برسالة: «تعذّرت قراءة ملف يلزم للتحليل… الملف مستخدم من برنامج آخر».

### السبب

يتبادل البرنامج ملفات التحكم مع صندوق العزل عبر مجلد مشترك. يُبقي ويندوز هذه الملفات مفتوحة للحظات بعد أن يقرأها الصندوق، وقد يفتحها مضاد الفيروسات أو فهرسة البحث أيضًا. فإذا حاول البرنامج تحديث الملف في تلك اللحظة رفض ويندوز ذلك، فيتوقف التحليل كله.

### ما تغيّر

- عند انشغال ملف، ينتظر البرنامج ويعيد المحاولة حتى ١٥ ثانية بدل التوقف فورًا. وإن بقي الملف مشغولًا، يكتب محتواه مباشرة في الملف نفسه.
- قراءة ملفك تتم بطريقة تسمح لبرامج أخرى بإبقائه مفتوحًا، مثل متصفح ما زال ينهي تنزيله أو مضاد فيروسات يفحصه.
- أداة المراقبة داخل الصندوق صارت تقرأ ملفات التحكم بطريقة لا تمنع البرنامج من تحديثها.
- رسالة الخطأ صارت تذكر **المرحلة** و**المكان** الذي حدث فيه الخلل، فإن تكرّر أي خطأ نعرف موضعه من صورة الشاشة مباشرة.

**المطوّر:** [mr-kateba](https://github.com/mr-kateba)

## Blazma Sandbox 0.1.2 — "file in use by another process" fixed

Analyses stopped with "The process cannot access the file because it is being used by another process". Files shared with Windows Sandbox can stay open on the host for a moment after the guest reads them (and antivirus or the indexer may open them too). Blazma now retries sharing violations for up to 15 s and falls back to an in-place write, reads the sample with full sharing, the agent no longer blocks the host from replacing control files, and failure messages name the stage and the code location.

**Developer:** [mr-kateba](https://github.com/mr-kateba)
