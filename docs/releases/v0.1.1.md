## Blazma Sandbox 0.1.1 — إصلاحات التشغيل على Windows 11

إصدار إصلاحات بعد أول تجربة حقيقية على Windows 11 Pro مع Windows Sandbox. كان البرنامج يُغلق فجأة أحيانًا، ويتوقف التحليل برسالة خطأ، ولا يعمل الملف داخل الصندوق. هذه أسبابها وما تغيّر:

### ما أُصلح

- **التحليل كان يتوقف فور بدئه على Windows 11 (24H2 وما بعده).** في هذه الإصدارات يُغلق `WindowsSandbox.exe` نفسه فور فتح النافذة، فكان Blazma يظن أن الصندوق أُغلق وينهي التحليل. صار يعرف حالة الصندوق من نبضات وكيل المراقبة، ومن الأمر `wsb` في الإصدارات الحديثة.
- **الملف لم يكن يعمل داخل الصندوق.** وكيل المراقبة كان يفشل في تشغيل مراقبة النواة (ETW) بسبب طريقة بنائه، فيتوقف قبل تشغيل الملف. أُصلح ذلك، وصار الملف يُشغَّل كما لو نقرت عليه مرتين، مع دعم أنواع أكثر (PDF وDOCX وHTA وغيرها)، ودون تحذيرات Windows التي كانت توقفه.
- **أمر بدء الوكيل قد لا يعمل في بعض إصدارات Windows Sandbox الحديثة** (مشكلة معروفة لدى Microsoft). صار للوكيل ثلاث طرق للبدء بدل طريقة واحدة.
- **مهلة البدء كانت قصيرة.** أول تشغيل للصندوق قد يستغرق عدة دقائق؛ صارت المهلة 8 دقائق.
- **الإغلاق المفاجئ للبرنامج:**
  - البرامج التي تشغّل نفسها مرات كثيرة كانت تُفشل حفظ التحليل.
  - تحديثات التقدّم الكثيرة كانت تجمّد النافذة.
  - فشل تحليل ملف واحد منشأ كان يُفشل التحليل كله.
  - صورة شاشة غير مكتملة كانت تُظهر خطأ مفاجئًا.
- **عطل واحد لم يعد يوقف كل شيء.** إذا فشل جزء اختياري (لقطات الشاشة، الإنترنت الوهمي، تسجيل الشبكة...) يستمر التحليل وتظهر ملاحظة بدل التوقف.

### تشخيص أوضح

- رسالة الخطأ تشرح السبب بالعربية، ومعها آخر أسطر من سجل وكيل المراقبة.
- سجل جديد من داخل الصندوق (`agent.log`) يُحفظ مع كل تحليل.
- إذا أُغلق البرنامج فجأة، يترك ملف `crash-*.txt` في مجلد السجلات: `%LocalAppData%\Blazma\Sandbox\logs`. أرسله لنا إن حدث ذلك.

> ما زال الإصدار تجريبيًا: هذه الإصلاحات مبنية على مراجعة دقيقة للكود ولوثائق Microsoft ومختبرة بأكثر من 850 اختبارًا آليًا، لكنها لم تُجرَّب بعد على جهازك. جرّبها وأخبرنا بالنتيجة.

## Blazma Sandbox 0.1.1 — Windows 11 fixes

Fixes after the first real run on Windows 11 Pro with Windows Sandbox:
- Analyses no longer stop right away on Windows 11 24H2+, where `WindowsSandbox.exe` exits as soon as the window opens; the sandbox is tracked through the agent's heartbeats and `wsb`.
- The agent now starts kernel tracing reliably (no native helpers needed), starts every kind of sample like a double-click, and survives component failures.
- The agent has three ways to start, for builds where the LogonCommand does not run.
- Longer start timeouts; app crashes and freezes on busy samples fixed.
- Clear failure reasons with the agent's own log; crash files in `%LocalAppData%\Blazma\Sandbox\logs`.

Still a preview: please try it and report back.
